# Ghostnotes

Lyria に弾いてもらったフレーズを耳コピして、ピアノロール上に「ゴーストノート」として重ねるミニ DAW。どの音を採用するかは人が1音ずつ決め、採用した理由も記録する。

DevFest Tokyo 2025 ハッカソン（テーマ "Own the Why, Build with Intent"）で、Lyria を使う案が実際に成り立つかを確かめるために作った試作。

## 何を解こうとしているか

チームの議論では、Lyria を使う案に次の2つの壁があった。

1. Lyria の出力は音声なので、一部だけを書き換えられない（inpainting ができない）。切り貼りすると継ぎ目が不自然になり、全体を作り直すと一貫性が失われる。
2. 生成された音を DAW で編集するには耳コピが要るが、AI の耳コピは難しい。

Ghostnotes では、曲の正本を MIDI にして、Lyria には提案だけをさせる。Lyria が弾いた音声を耳コピしてゴーストノートとして重ね、採用するかどうかを人が決める。音声を書き換えることはないので、1つ目の壁は問題にならない。2つ目の壁については、Lyria の出力の条件を絞れば耳コピの精度を上げられることを、下の検証で確かめた。

## 使い方

```bash
npm install
npm run dev   # http://127.0.0.1:5173
```

右上に Gemini API キーを入れる。キーはブラウザの localStorage にだけ保存する。開発用に `.env.local` へ `VITE_GEMINI_API_KEY=...` と書いておくこともできる。

1. Lead か Bass を選び、「どうしたいか」を日本語で書く（例:「ベースに寄り添う、少し切ないメロディ。最後の小節で上がって終わりたい」）。
2. 「Lyria に弾いてもらう」を押す。処理は次の4段階で進む。
   1. Gemini が意図と今の曲の中身を読み、Lyria へのプロンプトと設定（density、brightness など）を作る。選んだ理由も日本語で返す。
   2. Lyria RealTime が、曲と同じ BPM・キーで、対象パートだけを約14秒演奏する。
   3. basic-pitch（Spotify の採譜モデル）がブラウザの Web Worker で耳コピし、16分音符の格子・スケール・音域に合わせて単音に整える。
   4. Gemini が、提案されたフレーズの形と既存のベースとの関係を説明し、手で直すならどこかを1つ挙げる。
3. ピアノロール上の枠だけの音がゴーストノート。クリックで1音ずつ採用、右クリックで消去、Tab で全部採用する。実線は確からしい音、点線は誤検出の可能性がある音。
4. 上部の A／B／L で聴き比べる。A は自分のノートだけ、B はゴーストを MIDI で重ねた音、L は Lyria の原音を重ねた音。
5. 「拾う音の量」で整形の強さを変えられる（生成し直さない）。小節の頭がずれていれば「← 1/16」「1/16 →」で動かす。
6. 「理由を残して閉じる」で、意図・Lyria への指示・採用した音数・理由が「判断の記録」に残る。

## 検証で分かったこと（2026-11-06）

`scripts/` のスクリプトで、Lyria RealTime の出力を保存し、耳コピして測った。生成は各1回なので、傾向をつかむための数字として読んでほしい。

| 確かめたこと | 結果 |
|---|---|
| 応答の速さ | 最初の音が届くまで約3〜5秒。その後は実時間と同じ速さ（20秒分に約21秒） |
| 出力形式 | 48kHz、ステレオ、16bit PCM |
| キーの指定 | ピアノとベースは、耳コピした音の100%が指定したスケール内。シンセリードは91.7% |
| テンポの指定 | ドラムを 128 BPM で指定 → 推定 129.2 BPM、拍の間隔は 464ms（ばらつき 9ms）。100 BPM 指定のドラムは、推定ツールが 80.7 BPM と誤推定し、判定できなかった |
| 拍の格子への乗り方 | シンセリードは格子からのずれが平均 15.9ms（ランダムなら 37.5ms）で、ほぼ格子どおり。ベースは 34.7ms で、ほとんど乗っていなかった |
| ピアノ | 20秒で262音、同時に最大8音。和音と残響が多く、メロディとしては使えなかった |
| シンセリード | 整形後、2小節周期で同じ音が出ている箇所が27か所中19か所。Lyria が2小節のフレーズを繰り返していて、耳コピも毎回ほぼ同じ音を拾えている |
| ブラウザで通した場合 | 意図の入力からゴースト表示まで約50秒（ヘッドレスのソフトウェア描画での値）。内訳は Gemini 3〜5秒、Lyria 約17秒、耳コピ約27秒（うちモデルの初回読み込み約17秒） |

楽器の選び方で結果が大きく変わった。Gemini に楽器を自由に選ばせるとギターを選び、低い弦の音まで拾ってしまった。そこで、単音で耳コピしやすい楽器（リードはフルート、クラリネット、矩形波シンセなど、ベースはシンセベースなど）から選ばせるようにした。フルートで生成した例では、生の音91個から44音に整理でき、最後の小節で上がっていくフレーズになった。ただし、この評価は画面上の音の並びを見たもので、耳で聴いて確かめたものではない。

## 分かっている制約

- Lyria RealTime は音声もMIDIも受け取れない。既存のトラックは、Gemini が文章で説明したものしか伝わらない。
- 小節の頭は推定で、ずれることがある（手で動かせるようにしてある）。
- 耳コピは単音のパート（Lead／Bass）だけに対応している。ドラムと和音は対象外。
- API キーをブラウザから直接使っている。公開する前に、Cloud Run 経由にするか、短時間だけ有効なトークンに切り替える必要がある。
- 実際のユーザーには、まだ試してもらっていない。

## 次にやれそうなこと

- 2案を同時に生成して聴き比べる（PatchIntent 案の「2案比較」と組み合わせる）。
- 小節単位での採用、気に入ったゴーストだけを残した再生成。
- Firebase Hosting と Cloud Run で公開し、審査員がブラウザで試せるようにする。

## 構成

| パス | 役割 |
|---|---|
| `src/main.ts` | 画面と操作の流れ |
| `src/audio.ts` | Tone.js による再生（16分ごとに状態を読んで鳴らす） |
| `src/roll.ts` | ピアノロール（canvas） |
| `src/gemini.ts` | 意図 → Lyria の指示、提案の説明 |
| `src/lyria.ts` | Lyria RealTime の呼び出し |
| `src/transcribe.ts`, `src/transcribe.worker.ts` | basic-pitch による耳コピ（Web Worker） |
| `src/core/clean.js` | 耳コピ結果の整形（格子合わせ、単音化、音域とスケール合わせ） |
| `scripts/lyria-rt.mjs` | Lyria RealTime の出力を WAV に保存 |
| `scripts/transcribe.mjs` | WAV を耳コピし、スケール・格子への当てはまりを測る |
| `scripts/tempo.py` | librosa でテンポを推定（`uv run --with librosa==0.11.0 python scripts/tempo.py x.wav 100`） |
| `scripts/ghost-render.mjs` | 整形後の MIDI を鳴らし、元音声と聴き比べる mp3 を作る |
| `scripts/smoke.mjs` | Playwright で、意図の入力から採用・記録までを通しで確かめる |
