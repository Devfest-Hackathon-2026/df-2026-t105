# Ghostnotes を Cloud Run で公開する手順

中継サーバー（`server/index.mjs`）と画面を1つのコンテナにまとめ，Cloud Run（プロジェクト `dev-fast-deadline-driven`，リージョン `asia-northeast1`）で動かす．GeminiとLyriaはVertex AIで呼び，Gemini API（AI Studio）のキーは使わない．Vertexへは実行用サービスアカウント `ghostnotes-runtime` の権限で接続するので，コンテナにもブラウザにもAPIキーは入らない．サイトにはパスワード（Basic認証）をかける．

`main` が更新されると，GitHub Actions がデプロイする（`.github/workflows/deploy.yml`）．ビルドは Cloud Build が Google 側で行うので，Docker は要らない．

## 1. 準備（1回だけ）

### GCP

プロジェクトのオーナー権限を持つアカウントで，リポジトリの一番上で実行する．

```bash
APP_PASSWORD='<サイトのパスワード>' sh scripts/setup-gcp-ci.sh
```

このスクリプトは次を作る．何度実行してもよい．

- Secret Manager の `ghostnotes-app-password`（サイトのパスワード）と，`ghostnotes-runtime` への読み取り権限
- デプロイ用サービスアカウント `ghostnotes-deployer`（`roles/run.sourceDeveloper`，`roles/serviceusage.serviceUsageConsumer`，`ghostnotes-runtime` と `ghostnotes-build` の `roles/iam.serviceAccountUser`）
- Workload Identity Federation のプール `github` とプロバイダ `github`．`yi7242/ghostnotes` の `main` からだけ `ghostnotes-deployer` になれる

このプロジェクトは組織ポリシーでサービスアカウントの鍵を作れないので，GitHub Actions からは鍵を使わずに Workload Identity Federation で入る．

次のものは設定済みである．

- API：`run`，`cloudbuild`，`artifactregistry`，`secretmanager`，`aiplatform`
- `ghostnotes-runtime` の `roles/aiplatform.user`，`ghostnotes-build` の `roles/run.builder`

### GitHub

`yi7242/ghostnotes` の Secret に `SUBMISSION_REPO_TOKEN` を登録する．提出用リポジトリ（`Devfest-Hackathon-2026/df-2026-t105`）へ書き込める PAT を使う．ワークフローのファイルも push するので，classic なら `repo` と `workflow`，fine-grained なら Contents と Workflows の Read and write が要る．

## 2. デプロイ

`main` に push またはマージすると，次の2つが動く．Actions の画面から手動でも実行できる（workflow_dispatch）．

- **Deploy to Cloud Run**：`npm test` と `npm run build` のあと `gcloud run deploy --source .` でデプロイし，`/healthz` が 200，パスワードなしの `/api/config` が 401 を返すことを確かめる
- **Mirror to submission repository**：提出用リポジトリの `main` に push する．提出用リポジトリにしかないコミットがあると，上書きせずに失敗する

手動でデプロイするときのコマンドは README の「手動でデプロイする」を参照．

## 3. 確認

公開 URL を開くとパスワードを聞かれる．ユーザー名は何でもよい．パスワードを入れて `/api/config` を開き，`"backend":"vertex"` になっていることを確かめる．画面から生成し，音声と採譜結果が届けば成功である．実演用のデモモードは，URL の末尾に `?demo` を付ける．

Vertex では Lyria 3.5 と Lyria RealTime が使えない．画面の「Lyria 3.5」は Lyria 3 Pro で生成し，RealTime は選べなくなる．Lyria 3 Pro は1回の生成に約20秒，3 Clip は約10秒かかる（2026-11-10 に Vertex で確認）．

## 4. 公開中に気をつけること

- 中継サーバーは，IP ごとに10分あたり Gemini 60回，作曲 20回，採譜 40回まで受け付ける．足りなければ `server/index.mjs` の `LIMITS` を変える．回数はインスタンスごとに数えるので，`--max-instances 2` で利用料金の上限を抑えている．
- パスワードを変えるときは，`scripts/setup-gcp-ci.sh` を新しいパスワードで実行し，デプロイし直す．
- 審査期間が終わったら，`gcloud run services delete ghostnotes --region asia-northeast1` でサービスを消し，`gcloud secrets delete ghostnotes-app-password` でパスワードも消す．GitHub Actions を止めるときは，Workload Identity Federation のプール `github` を削除する．
