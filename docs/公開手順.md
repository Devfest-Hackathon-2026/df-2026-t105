# Ghostnotes を Cloud Run で公開する手順

> 現在の公開版（`dev-fast-deadline-driven`）は Vertex AI だけを使い，サイトにパスワードをかけ，GitHub Actions からデプロイしている．手順は README の「Cloud Runへのデプロイ」と `scripts/setup-gcp-ci.sh` を参照．以下は Gemini API のキーで動かす場合の手順として残す．

中継サーバー（`server/index.mjs`）と画面を1つのコンテナにまとめ、Cloud Run で動かす。API キーは Secret Manager に入れ、コンテナにもブラウザにも入れない。

ビルドは Cloud Build が Google 側で行うので、手元に Docker は要らない。必要なのは、GCP プロジェクトの編集権限と gcloud CLI だけである。Gemini API（AI Studio）を使うCloud Runへのデプロイと，画面の配信・接続先設定の確認を実施済み（2026-11-10）．

## 1. 準備（プロジェクトごとに1回）

```bash
PROJECT=<GCP のプロジェクト ID>
REGION=asia-northeast1
gcloud config set project $PROJECT
gcloud services enable run.googleapis.com cloudbuild.googleapis.com artifactregistry.googleapis.com secretmanager.googleapis.com

# Gemini API キーを Secret Manager に入れる（キーは履歴に残らないよう、環境変数から渡す）
printf %s "$GEMINI_API_KEY" | gcloud secrets create gemini-api-key --data-file=-

# Cloud Run の既定のサービスアカウントに、シークレットを読む権限を付ける
NUM=$(gcloud projects describe $PROJECT --format='value(projectNumber)')
gcloud secrets add-iam-policy-binding gemini-api-key \
  --member "serviceAccount:${NUM}-compute@developer.gserviceaccount.com" \
  --role roles/secretmanager.secretAccessor
```

## 1.5 Vertex AI（Agent Platform）で動かす場合

ハッカソンのクレジットは AI Studio の API キーには使えず、Vertex 経由なら使える。Vertex で動かすときは、Cloud Run のサービスアカウントに Vertex AI を呼ぶ権限を付け、`VERTEX_PROJECT` を渡す。

```bash
gcloud services enable aiplatform.googleapis.com
gcloud projects add-iam-policy-binding $PROJECT \
  --member "serviceAccount:${NUM}-compute@developer.gserviceaccount.com" \
  --role roles/aiplatform.user
```

配置のコマンドに `--set-env-vars VERTEX_PROJECT=$PROJECT` を足す。Vertex では Lyria 3.5 と RealTime が使えないので（2026-11-06 時点の Vertex の資料に載っていない）、画面の「Lyria 3.5」は自動で「Lyria 3 Pro」になり、RealTimeはAI Studioのキーがない場合に利用できなくなる。RealTime も使いたいときは、上の手順の AI Studio のキーも渡す（作曲と Gemini は Vertex、RealTime だけ AI Studio を使う）。

Vertex経由の音声生成が利用できるかは，使用するプロジェクトとモデルで確認する．

## 2. 配置

リポジトリの一番上で実行する。

```bash
gcloud run deploy ghostnotes --source . --region $REGION \
  --allow-unauthenticated \
  --update-secrets GEMINI_API_KEY=gemini-api-key:latest \
  --timeout 300 --max-instances 2 --memory 512Mi
```

- `--timeout 300`：Lyria の WebSocket は1回の提案で約20秒つながる。中継サーバー側でも60秒で切るので、300秒あれば足りる。
- `--max-instances 2`：中継サーバーの回数制限はインスタンスごとに数えるので、インスタンス数を絞って利用料金の上限を抑える。

表示された URL（`https://ghostnotes-xxxx.a.run.app`）を開き、APIキーの欄を空のまま「生成する」を押し，提案が届くかを確認する．既定は1案で，生成数と同時生成数はそれぞれ1〜4から選べる．実演用のデモモードは、URL の末尾に `?demo` を付ける。

## 3. 公開中に気をつけること

- 中継サーバーは、IP ごとに10分あたり Gemini 60回、Lyria 15接続まで受け付ける。同時接続は IP ごとに2本まで（2案ぶん）。足りなければ `server/index.mjs` の `LIMITS` を変える。
- 審査期間が終わったら、`gcloud run services delete ghostnotes --region $REGION` でサービスを消し、`gcloud secrets delete gemini-api-key` でキーも消す。
- Firebase Hosting の独自ドメインから Cloud Run に流す構成は、WebSocket が通るかを確かめていない。使う場合は、提案の生成まで試してから切り替える。
